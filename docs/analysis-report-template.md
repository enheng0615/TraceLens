# 逐案分析报告固定模板

本模板适用于项目今后编写的最终分析报告。自动生成的逐案报告包括在线反馈的 `feedback-report.md` 与评分差距归因的 `rca-report.md`，两个入口共用 `src/rca/report-template.mjs` 的开头结构。汇总分析若没有单一可证实根因，应在开头说明“尚未建立单一根因”，再按已观察的问题集合归类。运行日志、失败诊断和批次状态摘要不承载最终因果结论，保留各自格式。

```md
# <报告标题及案例标识>

## 根因及成因

<一句话说明最早有证据支持的原因或候选原因，以及它如何传递成最终结果；未定位时明确写“根因尚未定位”。>

## 问题类别

<一句话说明具体缺陷类型和发生环节；原因未定位时只归类已确认的现象。>

## 详细分析：从原因到用户反馈／最终结果

<用简短段落概括已观察事实、候选解释和调查状态。>

### 1. 当时的要求与预期

<当时有效的用户要求或评分合同，以及对应证据。>

### 2. 最早可定位的偏差及其形成机制

<精确到 Turn、Span、Tool 或字段，说明实际与预期如何分叉；区分可观察执行与尚未证实的决策原因。>

### 3. 偏差如何进入后续结果

<逐步写出下游读取、计算、写入和生成关系；每步引用 EV。>

### 4. 最终交付与用户反馈／最终表现

<将实际交付、用户主张或评分差距分别陈述，不把反馈原文当作已验证事实。>

### 5. 因果判断与剩余缺口

<已确认什么、尚未证明什么、下一步需要核验什么。>

## 字段级证据与引用

<原始片段、位置、EV、Tool/Skill 调用与可复核文件。>

## 核验信息

<调查状态、因果置信度、Trace 完整性与自动校验结果。>
```

写作约束：

- 开头只保留“根因及成因”和“问题类别”两个醒目的标题，各接一句话，不增加“结论摘要”或“两句话结论”标题。
- `localized_unverified` 写“候选原因（尚未证实）”；`symptom_only` 或 `unresolved` 写“根因尚未定位”。证据缺口、预算结束和最终回答片段都不能自动升格为根因。
- “为什么出现该偏差”只写 Trace 可观察的决策或执行依据；模型内部动机没有证据时明确为未知。用户主张、实际观测值和候选机制分别表述。
- 正文先讲从偏差到结果的传递，再给完整 Tool/Skill 审计和原始字段。所有关键事实保留 EV 或原始文件定位。
- 新报告的 `rootCauseHeadline` 和 `problemClassification` 在写入前校验。旧 JSON 重渲染时缺少字段，则以有范围的未定位或候选结论显示，不猜测类别。
